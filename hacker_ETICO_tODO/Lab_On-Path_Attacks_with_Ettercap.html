Objetivos

En esta práctica de laboratorio se cumplirán los siguientes objetivos:

  • Parte 1: Iniciar Ettercap y explorar sus funcionalidades
  • Parte 2: Realizar el ataque en ruta (MITM)
  • Parte 3: Usar Wireshark para observar el ataque de suplantación de ARP

Trasfondo / Escenario

Los ataques en ruta son formas muy potentes de robar datos que viajan por una red. Sin el cifrado de extremo a extremo, como sucede con muchos datos que viajan en las LAN locales, es fácil capturar información de texto sin cifrar, e incluso archivos completos, mediante métodos de ataque en ruta.

Nota: En ruta está reemplazando a man-in-the-middle (MITM) o hombre-en-el-medio como el nombre de este tipo de ataque. El proceso de reemplazo está incompleto; sin embargo, es posible que aún vea MITM en muchos lugares, incluidas algunas preguntas del examen. Solo tenga en cuenta que los dos términos son actualmente intercambiables.

Recursos necesarios

  • Kali VM personalizada para el curso de Ethical Hacker

Instrucciones

Parte 1: Inicie Ettercap y explore sus funcionalidades.

Ettercap se usa para realizar ataques en ruta (MITM). El objetivo de un ataque en ruta es interceptar el tráfico entre dispositivos para obtener información que pueda utilizarse para hacerse pasar por el objetivo o alterar los datos que se transmiten. El atacante se encuentra ”entre” dos hosts en comunicación. En los ataques en ruta, el hacker no necesita comprometer el dispositivo objetivo, sino que solo puede "olfatear" o rastrear el tráfico que va y viene entre el objetivo y el destino. Ettercap se utiliza como herramienta en ruta y la máquina de ataque está en la misma red IP que la víctima.

Paso 1: Configure un ataque de suplantación de ARP.

En este ataque, utilizará la suplantación de ARP para redirigir el tráfico en la red virtual local a su sistema Kali Linux en 10.6.6.1. La suplantación de ARP se utiliza a menudo para suplantar el enrutador de puerta de enlace predeterminado para capturar todo el tráfico que entra o sale de la red IP local. Debido a que su entorno de laboratorio utiliza una red virtual interna, en lugar de falsificar la puerta de enlace predeterminada, utilizará la suplantación de ARP para redirigir el tráfico destinado a un servidor local con la dirección 10.6.6.13.

  1. Cargue Kali Linux con el nombre de usuario kali y la contraseña kali. Abra una sesión de terminal desde la barra de menús en la parte superior de la pantalla.
  2. El host de destino en esta práctica de laboratorio es el dispositivo Linux en 10.6.6.23. Para ver la red desde la perspectiva del destino e iniciar el tráfico entre el destino y el servidor, utilice SSH para iniciar sesión en este host. El nombre de usuario es labuser y la contraseña es Cisco123.

El usuario del host 10.6.6.23 se comunica con el servidor en 10.6.6.13. El atacante en ruta en 10.6.6.1 (su VM de Kali) interceptará y retransmitirá el tráfico entre estos hosts.

  1. Abra una nueva sesión de terminal desde la barra de menús en Kali Linux. No cierre el terminal SSH que ejecuta la sesión con 10.6.6.23.
  2. Utilice el comando ettercap -h para ver el archivo de ayuda de la aplicación Ettercap.
┌──(kali㉿kali)-[~]

  1. Examine el contenido del archivo de ayuda.

Área de Respuesta
Hay cuatro interfaces de usuario disponibles y las opciones son -T, -C, -D, -G.
  1. En esta parte, usará una interfaz gráfica de usuario para acceder a Ettercap. Inicie la interfaz gráfica de usuario de Ettercap GTK+ con el comando ettercap -G. La mayoría de las funciones de Ettercap requieren permisos de root, así que use el comando sudo para obtener los permisos requeridos.

Parte 2: Realizar el ataque en ruta (MITM)

Paso 1: Seleccionar los dispositivos de destino.

  1. En la ventana GUI de Ettercap, abra la ventana Hosts List haciendo clic en el menú de Ettercap (icono de tres puntos). Seleccione la entrada Hosts y luego Hosts List. Haga clic en el icono Scan for hosts (lupa) en la parte superior izquierda de la barra de menús para buscar hosts vecinos. Aparece una lista de los hosts detectados en la red 10.6.6.0/24 en la ventana Host List (Lista de hosts).
¿Cuántos hosts se descubrieron?
Área de Respuesta
5

Al menos una de las direcciones MAC debe resultar familiar.

  1. Defina los dispositivos de origen y destino del ataque. Para ello, haga clic en la dirección IP 10.6.6.23 en la ventana para resaltar el host del usuario de destino. Haga clic en el botón Add to Target 1 en la parte inferior de la ventana Host List (Lista de hosts). Esto define el host del usuario como Target 1 (Objetivo 1).
  2. Haga clic en la dirección IP del servidor web de destino en 10.6.6.13 para resaltar la línea. Haga clic en el botón Add to Target 2 en la parte inferior de la ventana del host.

Cualquier dirección IP/MAC especificada como Target 1 tendrá todo su tráfico desviado a través de la computadora atacante que ejecuta Ettercap. En esta práctica de laboratorio, la computadora atacante es la máquina Kali Linux en 10.6.6.1. Todas las demás computadoras de la subred, excepto los destinos, se comunicarán normalmente.

  1. Haga clic en el icono de MITM en la barra de menús (el primer icono circular en la parte superior derecha). Seleccione ARP Poisoning... en el menú desplegable. Verifique que Sniff remote connections (Rastrear conexiones remotas) esté seleccionado. Haga clic en OK.
  2. Se inicia la explotación MITM. Si la detección no se inicia inmediatamente, haga clic en la opción Start (botón de reproducción) a la izquierda en el menú superior.

Paso 2: Realizar el ataque de suplantación de ARP.

  1. Regrese a la ventana de terminal que ejecuta la sesión SSH con el host del usuario de destino en 10.6.6.23. Repita el ping a 10.6.6.13.
labuser@3fb0515ea2f7:/$ ping -c 5 10.6.6.13
  1. Utilice el comando ip neighbor para ver la tabla ARP en 10.6.6.23 nuevamente. Tenga en cuenta la dirección MAC enumerada para 10.6.6.13.
¿La dirección MAC asociada con 10.6.6.13 es la misma que registró en la parte 1, paso 1e?
Área de Respuesta
No. Ahora es igual que la MAC de 10.6.6.1, la VM de Kali que ejecuta Ettercap.
¿Qué tiene de extraño?
Área de Respuesta
Se supone que las direcciones MAC son únicas a nivel global, por lo que es extraño que dos dispositivos tengan la misma dirección MAC.
¿Cuál es el efecto de este cambio?
Área de Respuesta
Los paquetes que se envían en la LAN a 10.6.6.13 serán recibidos tanto por el host previsto como por el atacante de la VM de Kali.
  1. Cierre la interfaz gráfica de usuario de Ettercap. Deje activa la conexión SSH a 10.6.6.23.

Paso 2: Abra Wireshark para ver el archivo PCAP guardado.

En este paso, examinará el archivo .pcap que creó Ettercap.

  1. Revise las direcciones MAC que registró en el Paso 1c. La dirección MAC para 10.6.6.23 se puede encontrar en la salida de la interfaz de texto de Ettercap en el grupo de objetivo 1.
¿Qué sucede ahora con las direcciones MAC de estos tres sistemas?
Área de Respuesta
10.6.6.23 (usuario objetivo) y 10.6.6.1 (atacante) tienen la misma dirección MAC. La dirección MAC para 10.6.6.11 (espectador) sigue siendo la misma porque no es el objetivo del ataque.
  1. En la ventana de terminal de Kali, inicie Wireshark con el archivo mitm-saved.pcap que creó con Ettercap.
┌──(kali@kali)-[~]
└─$ wireshark mitm-saved.pcap
  1. La computadora de ataque Ettercap primero difunde solicitudes ARP para obtener las direcciones MAC reales para los dos hosts de destino, 10.6.6.23 y 10.6.6.11. La máquina atacante comienza a enviar respuestas ARP a ambos hosts de destino utilizando su propia MAC para ambas direcciones IP. Esto hace que los dos hosts de destino dirijan las tramas de Ethernet a la computadora del atacante, lo que le permite recopilar datos como un atacante en ruta.
¿Por qué la computadora que ejecuta el ataque a Ettercap debe estar ubicada en la misma red IP que el sistema objetivo?
Área de Respuesta
Porque el protocolo ARP utiliza difusiones de capa 2 para obtener la MAC de destino asociada con la dirección IP de destino. Las difusiones y la información ARP de capa 2 no se reenvían más allá de la red local.

Reflexión
Mire el archivo mitm-Saved.pcap en Wireshark. Tenga en cuenta que el host atacante envía respuestas ARP a los dos objetivos varias veces durante la sesión de captura. Explique.
Área de Respuesta
Las entradas de la tabla ARP caducan de las tablas ARP locales después de un período de tiempo preestablecido. El envío repetido de actualizaciones de ARP mantiene las entradas falsificadas. Además, si otro host realiza una solicitud ARP a uno de los hosts de destino, el host responderá con su dirección MAC real. Esto no es un problema, a menos que los hosts de destino soliciten las direcciones MAC de los demás. Por lo tanto, para garantizar que esa explotación continúe sin interrupciones hasta que finalice, Ettercap se asegura de que las direcciones falsificadas permanezcan en las cachés ARP de los objetivos enviando numerosos mensajes de respuesta ARP con información falsa.
